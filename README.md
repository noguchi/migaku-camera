# みがくカメラ

USBカメラで静止画を撮影し、PNGとしてPCへ保存する日本語のWebアプリです。カメラ選択、ライブプレビュー、解像度選択、開始・停止、撮影結果の確認、写真の消去に対応します。接続したカメラはUSBに限らずブラウザーが認識する映像入力を含みます。

## 使い方

1. USBカメラを接続し、HTTPSで公開したページをPC版ChromeまたはEdgeの最新版で開きます。
2. カメラを選び「カメラを開始」を押し、ブラウザーのカメラ使用を許可します。許可前に機種名が見えない場合は、開始後に選択してください。
3. 必要ならカメラや解像度を変更します。映像を確認し「静止画を撮影」を押します。
4. 撮影結果を確認し「PNGをダウンロード」を押します。ファイル名には撮影したPCの現地日時が入ります。
5. 終了時は「停止」を押します。停止後も撮影した写真を保存できます。

写真は1枚だけ保持し、再撮影すると置き換わります。ページを離れると写真は消去されるため、必要な写真は先に保存してください。選択した解像度が機器非対応の場合は「カメラの標準」に戻してください。

## プライバシー

映像と写真は `getUserMedia`、`canvas`、ローカルのBlob URLを使い、ブラウザーのメモリー内だけで処理します。音声は取得しません。アップロード、分析サービス、外部ライブラリ、外部フォント、Cookie、画像の自動保存はありません。HTTPサーバーが配信するのはHTML・CSS・JavaScriptだけです。ページのContent Security Policyで `connect-src 'none'` を指定し、Fetch・WebSocket等の接続も制限しています。

ブラウザーの通信タブに表示される `blob:` は端末内の画像読み込みです。ネットワークへ送信される画像ではありません。写真は利用者がダウンロードしたときだけPC上のファイルになります。公開ホストには通常のページアクセス情報（IPアドレス等）が届きますが、映像や写真は送信しません。

## クラウド環境で開発・テスト

ビルド、npm依存関係、バックエンド、APIキーは不要です。既存のチェックアウトを使います。開発サーバーは次のコマンドで起動します。

```sh
cd /workspace/migaku-camera
python3 -m http.server 8000 --bind 127.0.0.1
```

ループバックHTTPはブラウザーの安全なコンテキストとして開発時のみ使用できます。利用者向け公開はHTTPSが必要です。

準備済みクラウド環境ではPython 3.12、Python Playwright、`/usr/bin/chromium`を利用します。

```sh
cd /workspace/migaku-camera
node --check app.js
python3 -m unittest discover -s tests -v
```

テストは専用のローカルHTTPサーバーを自動で起動・終了します。2台の仮想カメラでプレビュー、切替、4種類の解像度、PNGの実際のダウンロードとPNG内容・寸法・CRC、開始と停止、停止後の保存、写真の消去、遅れて許可されたストリームの停止、ページ終了時の解放、端末幅375pxのレイアウト、外部通信がないことを確認します。実際のブラウザーによる権限拒否と、HTTPでの利用拒否も確認します。未接続・使用中・非対応解像度・切断イベントはAPI応答のシミュレーションです。

別環境でテストする場合はPython PlaywrightとChromiumが必要です。Chromiumのパスを変える場合は `CHROMIUM_PATH` で指定できます。Playwright標準ブラウザーのインストールが必要な場合は公式手順に従い、`CHROMIUM_PATH` にその実行ファイルを指定してください。

## HTTPS公開

静的ファイル `index.html`、`style.css`、`app.js` だけを公開します。カメラを利用者のPCから直接取得するため、クラウドにUSBカメラを接続する必要はありません。

### GitHub Pages（ビルド設定不要）

今後は開発・公開ともに `main` ブランチを使用します。ルートの `.nojekyll` により静的ファイルをそのまま配信します。公開設定はリポジトリの [Settings → Pages](https://github.com/noguchi/migaku-camera/settings/pages) で次を選びます。

1. Source: **Deploy from a branch**
2. Branch: **main**、フォルダー: **/ (root)** → **Save**
3. 公開処理完了後、HTTPSが有効なことを確認します。表示されたURLをPCで開きます。

以後は `main` へのプッシュでサイトが更新されます。`gh-pages` へのプッシュは不要です。

公開URLは [https://noguchi.github.io/migaku-camera/](https://noguchi.github.io/migaku-camera/) です。HTTPSでHTML・CSS・JavaScriptが配信され、テスト済みファイルと一致することを確認しました。非公開リポジトリでPagesを使うには対応するGitHubプランが必要です。リポジトリの公開範囲を変更する場合は所有者が判断してください。非公開リポジトリでも、通常のPagesサイト自体は公開されます。

公開サイトを対象に同じブラウザーテストを実行できます。

```sh
CAMERA_TEST_URL=https://noguchi.github.io/migaku-camera/ python3 -m unittest discover -s tests -v
```

クラウド環境でChromiumが `ERR_CERT_AUTHORITY_INVALID` を返す場合は、環境が提供する通信プロキシCAをChromiumのNSS信頼ストアに登録し、そのストアを読み書き可能な状態で起動してください。証明書検証を無効にするオプションは不要です。アプリ利用者のPCでこのクラウド用証明書を登録する必要はありません。

Sitesが利用できる環境では、上記の静的ファイルをSitesに配置する方法を優先できます。このクラウド環境にはSites公開ツールがありません。GitHub Pagesを利用できない場合は、Netlify等の静的ホスティングで上記3ファイルのフォルダーをアップロードすれば、ビルド設定なしでHTTPS公開できます。公開サービスへのアカウント接続が必要です。

## USBカメラでの実機確認

クラウドの仮想カメラテストでは、USB機器のドライバー、実機画質、OSの権限、他アプリとの占有は確認できません。公開後に利用者のPCで以下を確認してください。

| 操作 | 確認する結果 |
| --- | --- |
| HTTPSページを開く | 開いただけではカメラの使用ランプが点かない |
| USBカメラを接続して「再検出」 | カメラを選択できる。許可後に機種名が表示される |
| 「カメラを開始」、使用を許可 | 選んだUSBカメラのライブ映像が表示される |
| 内蔵・USBカメラを切り替える | 選んだ機器の映像になり、前のカメラが停止する |
| 静止画を撮影しPNGをダウンロード | 撮影時点の写真が表示され、保存ファイルをPCで開ける。向き・色・画質・寸法を確認する |
| 解像度を変更 | 対応解像度では映像・写真の寸法が変わる。非対応では案内が出て、標準に戻すと再開できる |
| 「停止」、再度開始 | 使用ランプが消え、撮影は無効になる。写真は保存できる。再開すると再び映る |
| カメラを外す／接続し直す | 切断の案内が出る。「再検出」で復帰し、再度開始できる |
| 全カメラを外して開始 | 未接続の案内が出る |
| サイト設定でカメラを拒否して開始 | 権限の案内が出る。許可へ戻すと開始できる |
| 会議アプリ等でカメラを占有して開始 | 使用不可の場合は使用中・接続・OS権限の案内が出る。一部OS・機器は同時使用できるため、エラーにならない場合もある |
| 開始の許可待ち中に「停止」してから許可 | ライブ映像が開始されず、カメラが停止する |
| 別ページへ移動／タブを閉じる | カメラの使用ランプが消える。他のアプリが同時使用中なら、そのアプリも止めて確認する |
| 開発者ツール → Networkで撮影・保存 | HTML/CSS/JS以外の外部通信、画像POST、WebSocketが発生しない。`blob:` はローカル画像 |

ブラウザーの権限を拒否すると、アプリだけでは変更できません。アドレスバーのサイト設定とOSの「プライバシーとセキュリティ → カメラ」で許可を変更してください。

# みがくカメラ

USBカメラで静止画を撮影し、JPGとしてPCへ保存する日本語のWebアプリです。ページを開くとデフォルトカメラを自動で開始します。カメラ選択、ライブプレビュー、映像のクリック・スペースキーによる撮影、シャッター音、撮影画像の一覧、個別保存・削除に対応します。接続したカメラはUSBに限らずブラウザーが認識する映像入力を含みます。

## 使い方

1. USBカメラを接続し、HTTPSで公開したページをPC版ChromeまたはEdgeの最新版で開きます。
2. ページがカメラの使用を要求するので、初回はブラウザーで許可します。デフォルトカメラの映像が自動で表示されます。
3. 必要ならカメラを変更します。UIに覆われていない映像部分をクリックするか、スペースキーを押して撮影します。解像度は対応する最大のネイティブ映像サイズを自動で優先し、プルダウンはありません。
4. 右側の一覧に新しい画像が上から追加されます。各画像の「JPG保存」で保存できます。ファイル名には撮影したPCの現地日時・ミリ秒・撮影番号が入ります。
5. 必要な写真を保存してからページを閉じると、カメラを解放します。開始・停止・撮影ボタンはありません。カメラエラー後は「再検出」で再接続できます。

再撮影しても前の写真は残ります。個別の「削除」、または「すべて削除」で消去できます。ページを離れると全画像が消えるため、必要な写真は先に保存してください。画像はJPEG品質0.95で保存します。大きな画像を多数保持するとメモリーを使用します。画面には操作名・撮影データ・短いエラーだけを表示し、説明文を置いていません。

映像は画面全体に表示し、カメラ選択・右側の画像一覧を半透明のオーバーレイとして重ねます。一覧だけをスクロールできます。「画像」ボタンで一覧を開閉できます。狭い画面でも一覧は右側に表示します。プレビューは画面に合わせて拡大するため、画面比率によって上下または左右が切れますが、保存するJPGは元映像の全範囲・解像度を保持します。

撮影成功時にはAndroid標準カメラの「カシャッ」というシャッター音をWeb Audioで再生します。Android Open Source Projectの音源（Apache-2.0）をアプリに同梱し、外部からの音声取得やマイクの使用はありません。音源とライセンス・出典は `third_party/android/`、再生用の埋め込みデータは `shutter-sound.js` にあります。カメラ選択・保存・削除等の操作中はスペースキーで撮影せず、長押しでも連写しません。端末がミュートされている場合や音声出力を利用できない場合も撮影は続行します。

カメラの幅・高さには大きな `ideal` 値、`resizeMode` には `none` を指定し、ブラウザーが認識する最大のネイティブ映像サイズを優先します。実際に取得できる最大サイズは機器、ドライバー、ブラウザーに依存するため、実機では映像の寸法を確認してください。

## プライバシー

映像と写真は `getUserMedia`、`canvas`、ローカルのBlob URLを使い、ブラウザーのメモリー内だけで処理します。音声は取得しません。アップロード、分析サービス、外部ライブラリ、外部フォント、Cookie、画像の自動保存はありません。HTTPサーバーが配信するのはHTML・CSS・JavaScript（同梱音源のデータを含む）だけです。ページのContent Security Policyで `connect-src 'none'` を指定し、Fetch・WebSocket等の接続も制限しています。

ブラウザーの通信タブに表示される `blob:` は端末内の画像読み込みです。ネットワークへ送信される画像ではありません。写真は利用者がダウンロードしたときだけPC上のファイルになります。公開ホストには通常のページアクセス情報（IPアドレス等）が届きますが、映像や写真は送信しません。

## クラウド環境で開発・テスト

ビルド、npm依存関係、バックエンド、APIキーは不要です。既存のチェックアウトを使います。開発サーバーは次のコマンドで起動します。

```sh
cd /workspace/migaku-camera
python3 -m http.server 8000 --bind 127.0.0.1
```

ループバックHTTPはブラウザーの安全なコンテキストとして開発時のみ使用できます。利用者向け公開はHTTPSが必要です。

準備済みクラウド環境ではPython 3.12、Python Playwright、`/usr/bin/chromium`を利用します。

```sh
cd /workspace/migaku-camera
node --check app.js
python3 -m unittest discover -s tests -v
```

21件のテストは専用のローカルHTTPサーバーを自動で起動・終了します。2台の仮想カメラでデフォルトカメラの自動開始、能力情報と一致する最大解像度、プレビュー、カメラ切替、複数画像の新しい順の表示、実際のJPGダウンロードとJPEG内容・寸法、映像の複数箇所からのクリック・スペース撮影、キー長押し・UI操作による誤撮影防止、シャッター音と同梱Android音源の一致・実際の再生接続と音声非対応時の撮影、切断後の保存・再接続、個別・全削除、画像生成中の削除、遅れて許可されたストリームの停止、ページ終了時の解放、画面全体の映像、オーバーレイの操作・開閉・独立スクロールとPC・スマートフォンの縦横レイアウト、旧CSS・JavaScriptがキャッシュされた状態での更新、外部通信がないことを確認します。実際のブラウザーによる権限拒否と、HTTPでの利用拒否も確認します。未接続・使用中・利用不可・切断イベントはAPI応答のシミュレーションです。

別環境でテストする場合はPython PlaywrightとChromiumが必要です。Chromiumのパスを変える場合は `CHROMIUM_PATH` で指定できます。Playwright標準ブラウザーのインストールが必要な場合は公式手順に従い、`CHROMIUM_PATH` にその実行ファイルを指定してください。

## HTTPS公開

静的ファイル `index.html`、`style.css`、`shutter-sound.js`、`app.js` と `third_party/android/` の音源・ライセンス・出典を公開します。カメラを利用者のPCから直接取得するため、クラウドにUSBカメラを接続する必要はありません。

### GitHub Pages（ビルド設定不要）

今後は開発・公開ともに `main` ブランチを使用します。ルートの `.nojekyll` により静的ファイルをそのまま配信します。公開設定はリポジトリの [Settings → Pages](https://github.com/noguchi/migaku-camera/settings/pages) で次を選びます。

1. Source: **Deploy from a branch**
2. Branch: **main**、フォルダー: **/ (root)** → **Save**
3. 公開処理完了後、HTTPSが有効なことを確認します。表示されたURLをPCで開きます。

以後は `main` へのプッシュでサイトが更新されます。CSSやJavaScriptを変更する際は、`index.html` の読み込みURLに付けた `v` の値も更新し、旧ファイルと新しいHTMLが混在しないようにします。`gh-pages` へのプッシュは不要です。

公開URLは [https://noguchi.github.io/migaku-camera/](https://noguchi.github.io/migaku-camera/) です。HTTPSでHTML・CSS・JavaScriptが配信され、テスト済みファイルと一致することを確認しました。非公開リポジトリでPagesを使うには対応するGitHubプランが必要です。リポジトリの公開範囲を変更する場合は所有者が判断してください。非公開リポジトリでも、通常のPagesサイト自体は公開されます。

公開サイトを対象に同じブラウザーテストを実行できます。

```sh
CAMERA_TEST_URL=https://noguchi.github.io/migaku-camera/ python3 -m unittest discover -s tests -v
```

クラウド環境でChromiumが `ERR_CERT_AUTHORITY_INVALID` を返す場合は、環境が提供する通信プロキシCAをChromiumのNSS信頼ストアに登録し、そのストアを読み書き可能な状態で起動してください。証明書検証を無効にするオプションは不要です。アプリ利用者のPCでこのクラウド用証明書を登録する必要はありません。

Sitesが利用できる環境では、上記の静的ファイルをSitesに配置する方法を優先できます。このクラウド環境にはSites公開ツールがありません。GitHub Pagesを利用できない場合は、Netlify等の静的ホスティングで上記ファイルとライセンスを含むフォルダーをアップロードすれば、ビルド設定なしでHTTPS公開できます。公開サービスへのアカウント接続が必要です。

## USBカメラでの実機確認

クラウドの仮想カメラテストでは、USB機器のドライバー、実機画質、OSの権限、他アプリとの占有は確認できません。公開後に利用者のPCで以下を確認してください。

| 操作 | 確認する結果 |
| --- | --- |
| HTTPSページを開き、カメラの使用を許可 | デフォルトカメラのライブ映像が自動で表示され、使用ランプが点く |
| USBカメラを接続して「再検出」 | カメラを選択できる。許可後に機種名が表示される |
| 内蔵・USBカメラを切り替える | 選んだ機器の映像になり、前のカメラが停止する |
| 複数回撮影し、各画像のJPGをダウンロード | 一覧の上が最新で、以前の写真も残る。保存ファイルをPCで開き、向き・色・画質・寸法を確認する |
| ライブ映像とJPGの寸法を確認 | カメラ・ブラウザーが対応する最大解像度で取得されている。手動の解像度選択はない |
| 画像を個別に削除し、最後にすべて削除 | 選んだ画像だけが削除され、全削除後には一覧が空になる |
| 映像の複数の場所をクリックし、スペースキーでも撮影 | 操作ごとに1枚増え、シャッター音が聞こえる。ミュート解除とスピーカー音量も確認する |
| スペースキーを長押し／カメラ選択・JPG保存・削除の操作 | 連写せず、UI操作による意図しない撮影がない |
| カメラを外す／接続し直す | 切断の案内が出る。「再検出」で映像が再開する |
| 全カメラを外してページを開く | 未接続の案内が出る |
| サイト設定でカメラを拒否してページを開く | 権限の案内が出る。許可へ戻して「再検出」を押すと再開できる |
| 会議アプリ等でカメラを占有してページを開く | 使用不可の場合は使用中・接続・OS権限の案内が出る。一部OS・機器は同時使用できるため、エラーにならない場合もある |
| カメラの許可待ち中にページを離れる | 後から許可してもカメラを使い続けない |
| 別ページへ移動／タブを閉じる | カメラの使用ランプが消える。他のアプリが同時使用中なら、そのアプリも止めて確認する |
| 開発者ツール → Networkで撮影・保存 | HTML/CSS/JS以外の外部通信、画像POST、WebSocketが発生しない。`blob:` はローカル画像 |

ブラウザーの権限を拒否すると、アプリだけでは変更できません。アドレスバーのサイト設定とOSの「プライバシーとセキュリティ → カメラ」で許可を変更してください。
